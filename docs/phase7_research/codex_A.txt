- キモは「SQL 代入」ではなく「既に型付きの engine record から MySQL record image へ materialize」している点。`Field::store()` の charset/文字列検証/数値 parse を通らない。

- `Field_long::store(char*)` は文字列を `strntoull10rnd()` で parse する: `sql/field.cc:3653-3661`, `:1596-1612`.
- `Field_string::store()` / `Field_varstring::store()` は `field_well_formed_copy_nchars()` で charset 変換/検証する: `sql/field.cc:6129-6150`, `:6574-6590`.

3. **cherry-pick 可否**
- 可。ただし現在の LineairDB value は `set_write_buffer()` が `Field::val_str()` で作る「表示/文字列寄り」の列 slice: `proxy/ha_lineairdb.cc:4865-4881`. そのまま全型 `memcpy` は不可。

- 変更後の流れ: `Field::store()` loop を消し、`materialize_column(buf + off, templ, slice)` に置換。NULL は `table->s->default_values + off` を copy して null bit 維持。BLOB は `blobroot` に payload copy して `Field_blob::set_ptr()` を直接呼ぶ。現行の後段 blob copy は `proxy/ha_lineairdb.cc:4890-4899`.
- 最短案: 既存 text format に対し、CHAR/VARCHAR/BLOB は direct copy/length-prefix/pad、INT/DATE/DECIMAL は当面 fallback `Field::store()`。効果は限定的だが安全。
- 本命案: KV value v2 または proxy row cache sidecar に「MySQL record-format column bytes」を持つ。fixed は `memcpy`、VARCHAR は length prefix + payload、BLOB は payload + `set_ptr()`。これで InnoDB と同じ型付き copy になる。

4. **移植の制約/リスク**
- InnoDB は engine record が型付き binary。helios は現在 `val_str()` 由来なので numeric/date/decimal が文字列 parse 必須。ここを変えない限り InnoDB 級にはならない: `proxy/ha_lineairdb.cc:4877-4879`.
- server 側 predicate pushdown は現在 row value を文字列 slice として parse する: `server/rpc/predicate_evaluator.cc:20-27`, `:124-160`. binary-only value にすると filter/value-column binding が壊れる。
- value-column binding も decimal string を `strtoll()` して key 化している: `server/rpc/lineairdb_rpc.cc:226-231`.
- MySQL record image は TABLE metadata, charset, MySQL version, pointer size/endianness に依存する。remote KV の永続 value にするなら format version/schema id/migration が必要。
- BLOB は record 内が pointer なので、そのまま永続化不可。payload を cache/row arena に copy して record には pointer を張る必要がある。InnoDB も BLOB は heap に copy してから ref 化する: `row/row0sel.cc:2847-2868`, `:2604-2608`.

5. **実装規模の見積もり**
- **M**: proxy-only template + text-format fast path。`set_fields_from_lineairdb()` の `Field::store()` を common型から順に外す。期待効果は `set_fields` 部分 30-60% 減、リスク低。
- **L**: value v2/sidecar record-image cache + server predicate 互換維持。期待効果は `set_fields` をほぼ parse+memcpy/BLOB set_ptr 化し、5.9s の大半を削れる可能性が高い。ただし remote format と server filter まで触る。
